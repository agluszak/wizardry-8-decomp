# `srEXT_JPEGImporter.dll` target

This SurRender extension combines pristine IJG JPEG release 6 with a small Sir-Tech codec adapter,
SurRender plug-in classes, and VC6 runtime glue. Its CodeView path places the original project in
the SurRender SDK extension tree rather than Wizardry gameplay source.

Canonical identities and evidence live in
`evidence/reviewed/srext-jpegimporter/functions.csv`; reccmp's operational projection remains in
`config/reccmp/`. Current identity totals are generated by `just wiz8 report status`.

## Binary and SDK boundary

The DLL exports `srGetLibraryVersion` at ordinal 1 and `srInitPlugin` at ordinal 2. The recovered
version function returns `0x012A0209`. The factory constructs a plug-in wrapper owning an embedded
importer/exporter object and registers both `jpg` and `jpeg` surface types.

Exact decorated imports from `SR.DLL` establish the calling conventions and multiple-inheritance
interfaces used by the plug-in. The reviewed import observations are in
`evidence/observations/surrender/jpeg-sr-imports.csv`; the matching minimal import-library
definition is `src/srext_jpegimporter/sr-jpeg-imports.def`.

Recovered declarations under `include/surrender/` model:

- the virtual `srBinStream` base used by directional streams;
- importer and exporter subobjects;
- the surface-description and pixel-format records;
- the observed `srColorSurface` virtual interface.

Unknown SDK fields remain positional. The declarations represent the proven prefix used by this
extension, not an assertion that no later SDK revision extended the records.

## Recovered behavior

The importer validates JPEG headers, creates SurRender color surfaces, and converts decoded rows.
The exporter recognizes the `QUALITY` option, clamps it to the accepted floating-point range, and
stores the truncated percentage used by the IJG encoder.

The stdio bridge is intentional adapter code, not CRT code: its read and write replacements catch
SurRender stream exceptions and rethrow the original input- or output-corruption diagnostics.
`DllMain` disables thread notifications only on process attach.

The object layout is represented in `src/srext_jpegimporter/layout.h`. A plug-in wrapper owns the
importer/exporter subobject; that subobject contains distinct importer and exporter vptrs, codec
operation state, and export options. The concrete surface wrapper adds no data beyond its recovered
base and exists to install the extension-local virtual table.

## Matching build

Build and compare with:

```sh
just build SREXT_JPEGIMPORTER
just compare SREXT_JPEGIMPORTER
```

The CMake target compiles the pinned IJG release-6 source directly with VC6 SP5, then links the
recovered adapter and plug-in in original object order. Stream-transfer methods retain exception
handling because the original emits SEH frames there; lifetime functions remain in a separate
exception-disabled unit so VC6 does not add spurious prologues.

Repeated IJG private names are qualified in debug symbols only, resolving comparison pairing
without changing machine code. The original omission of selected stdio destination helpers is also
preserved rather than linking unused upstream code.

## Stable recovery lessons

- Vtable references exposed real starts omitted by initial auto-analysis. Applied identities may
  therefore create functions before naming them.
- FID can identify identical upstream bodies but cannot resolve identical-body pairs by itself;
  object order, PDB ownership, call graph, and surrounding source sequence provide that boundary.
- `__declspec(novtable)` on imported abstract interfaces avoids emitting local base vtables and a
  spurious `_purecall` dependency.
- Exception settings are translation-unit evidence. Enabling them globally changes unrelated
  prologues; disabling them globally deletes required cleanup state.

## Runtime replacement proof

The replacement was exercised against the original `sr.dll` in an isolated copy of the game tree.
A VC6 harness called the real plug-in factory and importer/exporter vtables, covering JPEG metadata,
pixel import, export options, cleanup, repeated loading, and unload. Runtime artifacts belong under
the external work directory; they are not duplicated as tracked status tables here.

The target demonstrated the complete compiler, linker, Ghidra, comparison, and replacement-DLL
workflow. Further progress should focus on recovered Wizardry translation units rather than growing
this document's historical match inventory.
